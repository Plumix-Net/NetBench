# E2E-тесты мобильного NetBench

Сквозные сценарии настоящего приложения на Android-эмуляторе и iOS-симуляторе —
[Maestro](https://maestro.mobile.dev), один набор флоу на обе платформы. Дополняют headless-тесты
`NetBench.Mobile.Tests`: здесь работают сборка под платформу, хост Plumix, мост доступности, клавиатура,
сеть и файловая система устройства.

## Запуск

```bash
brew install mobile-dev-inc/tap/maestro   # один раз; нужна Java 17+

scripts/e2e.sh android                     # эмулятор уже загружен
scripts/e2e.sh ios                         # симулятор уже загружен
scripts/e2e.sh android --no-build e2e/flows/home.yaml
```

Скрипт собирает и ставит приложение (Android — Debug APK со сборками внутри; iOS — Release под
`iossimulator-arm64`: Debug под симулятор падает при старте рантайма), поднимает цель для прогонов —
`python3 -m http.server` на `127.0.0.1:8099` (эмулятору её пробрасывает `adb reverse`) — и запускает
все флоу из `flows/`. Устройство — `ANDROID_SERIAL` / `IOS_SIMULATOR`, иначе первое найденное.
Отчёт JUnit, скриншоты и логи упавших шагов — в `artifacts/e2e/<платформа>/`.

Флоу берут адрес цели из `TARGET`, который передаёт скрипт; при запуске `maestro test` напрямую —
`-e TARGET=http://127.0.0.1:8099/` и своя цель на этом порту. Эмулятор и симулятор одновременно на 16 ГБ
не тянут: система на эмуляторе ловит ANR, и флоу падают на старте — гоняй платформы по очереди.

## Флоу

| Файл | Что проверяет |
|---|---|
| `flows/home.yaml` | Главный экран чистой установки |
| `flows/quick_test_run.yaml` | Быстрый тест: согласие «только свои серверы», живой прогон, стоп, результат, история |
| `flows/scenario_editor.yaml` | Новый сценарий: валидация адреса, сохранение, карточка, прогон из списка |
| `flows/abort_run.yaml` | Системный «назад» на мониторе спрашивает, прерывать ли прогон (только Android) |
| `flows/settings_language.yaml` | Смена языка перестраивает UI и переживает перезапуск |

`subflows/` — общие шаги: чистый запуск, остановка прогона.

## Как писать флоу

- Элементы ищутся по дереву доступности — тому же, что читают TalkBack и VoiceOver: по подписи
  (`tapOn: Quick test`) или по идентификатору (`tapOn: { id: quick_test_url }`).
- Идентификаторы — `Semantics(identifier:)`, константы в `NetBench/Mobile/AutomationIds.cs`
  (Android — resource-id, iOS — accessibilityIdentifier). Нужны текстовым полям: Android отдаёт наружу
  значение поля, а не его подпись.
- Сливающиеся узлы (карточка метрики — «REQUESTS / SEC\n217») ищутся регэкспом: `"(?is)requests / sec.*"`.
- Семантика Plumix включается первым запросом дерева, поэтому `subflows/launch_clean.yaml` ждёт главный экран
  с запасом, а запуск повторяет: Android изредка убивает свежий процесс сразу после `clearState`.
- Тап во время перехода между экранами теряется (Navigator не пускает указатель на время анимации), на iOS
  тапы изредка теряются и без перехода — навигационным тапам ставь `retryTapIfNoChange: true`.
- Пресеты (пользователи, длительность, метод) выбирай до ввода текста: экранная клавиатура закрывает нижние ряды.
- Монитор прогона перерисовывается непрерывно, снимок дерева на нём занимает до ~15 с: на нём только
  `extendedWaitUntil` с таймаутом 60 с, «Стоп» — в цикле (`subflows/stop_run.yaml`), а прогоны — на 5 минут,
  чтобы не кончились раньше.
- Android отдаёт наружу только узлы в видимой части прокрутки — до нижних блоков `scrollUntilVisible`.
  Подсказка и текст ошибки поля на iOS уходят в accessibilityHint, который Maestro не видит.
- Тексты — английские (культура устройства en-US); подписи меняются вместе с флоу.
